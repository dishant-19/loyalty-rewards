# BoxBonus — Customer Loyalty Rewards System

A responsive PHP loyalty website for a factory selling physical products in boxes. Customers create an account, enter a unique code from inside a purchased box, and earn points. Factory staff generate secure codes and monitor programme activity from an admin dashboard.

## Features

- Customer registration and login with server-side validation and password hashing.
- Unique one-time box codes, generated by the factory admin.
- Customers claim points by entering the code inside the packaging.
- Codes are hashed at rest, have a unique database constraint, and are redeemed inside a transaction to prevent reuse/double claims.
- Admin dashboard with customer count, generated/redeemed code totals, points in circulation, redemption rate, recent activity, secure code generation, and a pending reward-request approval queue.
- Customer reward requests: a ₹50 shopping voucher costs 100 points; points are deducted on submission, each request resets the 100-new-points progress cycle, admins can approve/reject, and rejected requests automatically refund the points and restore the previous progress.
- In-app customer/admin notification inboxes: request submitted, approved, rejected, and refunded events; unread counters in the navigation; mark-all-read controls. Notification records are written in the same database transaction as the reward workflow.
- Dark/light theme toggle, responsive layout, cinematic landing page with an interactive Three.js WebGL gift box, particle effects, metallic materials, and reduced-motion support.
- CSRF protection, output escaping, prepared SQL statements, session ID regeneration, and role checks.

## Tech stack

- PHP 8.1+
- MySQL 8.0+ via PHP PDO MySQL extension
- HTML5, CSS3, vanilla JavaScript
- No framework, build step, Composer package, or API key required

## Setup and run

1. Install PHP 8.1+ with the `pdo_mysql` extension enabled, plus MySQL 8.0+ (XAMPP/WAMP is suitable).
2. Extract this repository and start Apache/PHP and MySQL.
3. Create the database using **phpMyAdmin**: open `http://localhost/phpmyadmin`, import `database.sql`, or run that file in the SQL tab. It creates the `boxbonus` database and required tables.
4. Configure the connection in `config.php` (the `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASS` environment variables are supported). For a default XAMPP setup, the fallback settings are `127.0.0.1:3306`, database `boxbonus`, user `root`, and an empty password. Set a strong password in production.
5. From the project folder, run:

   ```bash
   localhost/loyalty-rewards-php/
   ```

4. Open [http://localhost/loyalty-rewards-php/](http://localhost/loyalty-rewards-php/).
5. Register a customer account, or sign in with the demo admin account:
   - Email: `admin@example.com`
   - Password: `Admin@12345`

The app connects to MySQL through PDO in `config.php`. Tables are created automatically when the app first runs (the database itself must already exist); you can also import `database.sql` manually.

## Factory workflow

1. Sign in as admin.
2. In **Generate box codes**, choose quantity and points per box.
3. Save or print the generated codes immediately. The clear-text values are only shown once.
4. Put one code inside each corresponding product box (preferably on a tamper-evident insert).
5. Customer registers/signs in and enters the code in **Claim your points**.
6. The code is checked and atomically marked redeemed; points are credited to the customer.
7. Once the customer has earned 100 new points since their previous request, they can request the ₹50 shopping voucher. The 100 points are deducted immediately and their next 100-point progress cycle starts.
8. Customer and admin receive in-app notifications when the request is submitted. Admin reviews the request in **Pending reward requests**. Approval sends the customer an approval notice; rejection sends a rejection notice and a separate points-refunded notice while restoring the customer's previous reward progress. Both roles can open their inbox from the top navigation and mark all notifications read.

## Validation and security notes

Every rule is enforced **twice**: live in the browser (`assets/ux.js`, for instant feedback) and again on the server (the authority — client checks are never trusted).

- Customer name: 2–80 characters; letters, spaces, apostrophes, dots and hyphens only.
- Email: required, valid format, no whitespace, max 190 characters, unique (friendly duplicate message + database unique index).
- Password: 8+ characters, at most 72 bytes (bcrypt limit), at least one uppercase letter and one digit; must be confirmed on registration. Live strength meter, requirement checklist, show/hide toggle and Caps Lock warning.
- Login: email format + non-empty password; credential failures use one generic message (no account enumeration).
- Box code: spaces/dashes are ignored, letters/digits only, exactly 12 characters, input capped at 40 raw characters; the field auto-uppercases and shows a live 12-segment meter.
- Admin batch: 1–100 codes and 1–1000 points per code, whole numbers only, with per-field messages.
- Admin/customer action ids and decisions: type-checked (array or malformed values are rejected, no PHP warnings).
- Forms lock after a valid submit (spinner, double-submit guard) and unlock if the page is restored from the back/forward cache.
- All state-changing forms use CSRF tokens; SQL uses prepared statements; output is HTML-escaped.
- A production deployment should use HTTPS, change/remove the seeded demo admin credentials, add login/claim rate limiting, email verification, password reset, monitoring, backups, and a formal code print/fulfilment process.

## Design layer (3D animation, UI/UX)

**Real WebGL 3D (`assets/three-fx.js`, Three.js from the jsDelivr CDN):**
- A full-page 3D world behind every page: gift boxes, gold coins and star-dust. The camera glides through it as you scroll, follows the mouse, spins things faster when you scroll quickly, "warps" forward when you navigate, and fires a 3D coin burst when you earn points.
- Dashboard: an interactive 3D gold coin (drag to spin, click to flip).
- Admin: a 3D radial bar-ring gauge of the redemption rate that builds up on load (drag to rotate).
- Login/Register: an interactive 3D gift box (drag to rotate, click or Enter to open the lid).
- Landing page: the existing hero gift box plus scroll-driven 3D tilt on sections; all pages use 3D page-leave transitions.
- If WebGL or the CDN is unavailable, the CSS 3D layer below remains as a fallback. Scenes pause when off-screen or the tab is hidden.

**CSS 3D layer:**

- `assets/design-3d.css` and `assets/ux.js` sit on top of the original stylesheet/script; no business logic lives in them.
- Floating 3D wireframe cubes and a moving perspective floor with mouse parallax, 3D page/card entrances, pointer tilt with a moving glare, tactile 3D buttons with ripple, a spinning coin on the points card, flip-in metric cards, count-up numbers, animated progress bars, slide-in lists, toasts, a scroll-progress bar and a confetti burst on success.
- Accessibility: skip link, visible focus rings, `aria-invalid`/`aria-describedby`/live regions on fields, and full `prefers-reduced-motion` support (all movement is removed, layout unchanged). Touch devices skip hover-only effects.
